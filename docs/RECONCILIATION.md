# Manual n8n reconciliation\n\nIf creation has an unknown outcome, do **not** POST again. Query the deployment status and inspect the existing workflow in n8n. If the stored workflow ID is known, that ID is persisted even when readback fails.\n\nRun `ai-automation-builder reconcile IDEMPOTENCY_KEY N8N_WORKFLOW_ID` in an interactive operator-owned terminal. The command requires a fresh confirmation challenge and performs **GET only**. It verifies the graph and inactive state, then atomically transitions `uncertain` to `created_inactive`. The operator must identify the exact workflow ID if creation timed out before receiving its ID. Failed verification never re-creates or activates anything.\n\nThe MCP and REST interfaces intentionally cannot reconcile. The remaining race between provider readback and provider changes is not eliminated: use n8n IAM controls and audit logs. Staging validation is required.\n
